Express Lab

Node.js с нуля + ShareBox на Express, в двух частях

Node.js с нуля в двух частях перед TypeScript и NestJS: рантайм и протокол HTTP, свой сервер, процессы, архитектура, роутер Express и middleware, ошибки и zod, PostgreSQL и Prisma 7, JWT с ротацией refresh, файлы потоком до 200 МБ, share-ссылки, тесты, Docker, два финала без подсказок.

Стек: Node 24, Express 5, PostgreSQL 18, Prisma 7, Docker. Уровень: Низкая–средняя.

routes → controllers → services

Роут знает про req/res, контроллер связывает роут и логику, сервис не знает про Express вообще — его можно вызвать и из теста, и из консоли. Стрелка зависимости — в одну сторону.

  • routes: какой адрес к какой функции
  • controllers: разобрать req, собрать res
  • services: чистая логика, без HTTP

Один обработчик на всё приложение

Четырёхаргументный middleware (err, req, res, next) — Express находит его по сигнатуре и зовёт при любой брошенной или переданной через next(err) ошибке. Свои классы ошибок несут HTTP-статус с собой.

  • class AppError extends Error { status }
  • throw — поймано один раз, не в каждом роуте
  • 404 и 500 без утечки деталей клиенту

Access живёт минуты, refresh — дни

Короткий access летает в каждом запросе; долгий refresh хранится отдельно и только обновляет пару токенов. Ротация — каждый refresh выдаёт новую пару взамен старой, а не продлевает прежнюю.

  • jwt.sign({ sub, type }, secret, { expiresIn })
  • requireAuth — middleware, кладёт req.user
  • 403 (чужое) ≠ 401 (не вошла)

Файл до 200 МБ без роста памяти

createReadStream(...).pipe(res) отдаёт файл кусками, не читая целиком в память — тот же приём, которым в сессии 2 копировали файл. Range-запрос просит только часть файла — так устроена докачка.

  • multer пишет на диск потоком, с лимитом
  • случайное имя на диске — защита от path traversal
  • Range → 206 Partial Content
