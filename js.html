Чистый JS Lab

Vanilla Helpdesk — фундамент без фреймворка

Чистый JavaScript с нуля — общий фундамент для Vue и TypeScript: var/let/const и hoisting, this и замыкания, прототипы и class, event loop и async/await, DOM без фреймворка, ESM-модули, своя реактивность на Proxy, финальное мини-SPA с явным сравнением с Vue.

Стек: JavaScript ES2022, Node.js 24+, json-server, node:test, Docker. Уровень: Средняя.

Область видимости и замыкание в цикле

Разберётесь, почему var делает одну переменную на весь цикл, а let создаёт новую на каждой итерации. Ловушка: асинхронные колбэки видят финальное значение счётчика.

  • var — функциональная область, let/const — блочная
  • Hoisting и Temporal Dead Zone
  • let в for создаёт новое связывание на итерацию

this определяет вызов, а не объявление

Четыре способа вызова функции дают четыре разных this. Стрелочная функция берёт this из окружающего контекста и не переопределяется.

  • fn(), obj.method(), call/apply/bind, new
  • bind фиксирует this навсегда
  • Стрелка внутри метода решает потерю this в колбэке

class — синтаксис над прототипами

Цепочку прототипов можно собрать вручную через Object.create, а class даёт тот же механизм в удобной форме. Вывод: методы класса лежат в prototype, а не в каждом экземпляре.

  • Поиск свойства идёт вверх по цепочке прототипов
  • extends и super явно связывают родителя
  • typeof класса — "function"

Microtask раньше macrotask

JavaScript однопоточный, а асинхронность — это порядок очередей. Ловушка: setTimeout(fn, 0) всегда выполняется после промисов.

  • Сначала синхронный код до пустого стека
  • Очередь microtask опустошается целиком
  • Затем одна macrotask и снова microtask

Ошибки fetch и AbortController

fetch не бросает исключение на 404 и 500, только на сетевой сбой, поэтому response.ok надо проверять вручную. Устаревший запрос при быстром вводе отменяется через AbortController.

  • Проверка response.ok обязательна
  • AbortError — ожидаемая отмена, а не сбой
  • Promise.all, allSettled, race и any для нескольких запросов

Один обработчик на родителе

Вместо обработчика на каждом элементе списка вешается один на контейнер и использует всплытие событий. Он работает и для элементов, которых ещё нет.

  • event.target.closest находит нужный элемент
  • Ранний return для кликов мимо
  • Не нужно перевешивать обработчики после рендера
