Inertia Lab

Inkwell — блог-платформа

Laravel 13 + Inertia 3 + Vue 3 без starter kit, на блог-платформе «Inkwell»: протокол на проводе и объект страницы, props как публичный API через Resources, формы и валидация без 422, SSR и мета-теги, hydration mismatch и утечка Pinia между посетителями, optional/defer/merge для отложенных props, роли и Policies без дублирования прав на фронте, typed routes через Wayfinder.

Стек: Laravel 13, Inertia 3, Vue 3, TypeScript, Pinia. Уровень: Средняя.

HTML один раз, дальше — JSON

Первый визит — обычный GET: Laravel рендерит app.blade.php с объектом страницы внутри <script type="application/json">. Каждый следующий клик по <Link> — XHR с заголовком X-Inertia: true на тот же URL; в ответ приходит тот же объект страницы, но уже application/json. Один маршрут обслуживает и HTML, и JSON — отдельного REST API нет.

  • component + props + url + version в каждом ответе
  • X-Inertia-Version расходится → 409 → полная перезагрузка
  • history.pushState хранит объект страницы для кнопки «назад»

Resource вместо модели целиком

Inertia::render('Posts/Show', ['post' => $post]) сериализует модель в JSON целиком — в браузер уйдёт всё, включая user_id и непоказанные поля. Каждая «форма» данных получает свой ресурс: PostCardResource для карточки в ленте, PostResource — для страницы поста с телом.

  • Ресурс — белый список полей, как DTO на выходе
  • $hidden защищает по чёрному списку, ресурс — по белому
  • Markdown рендерится на сервере, в props уходит готовый HTML

Почему редирект после PUT не повторяет метод

После PUT /studio/posts/5 обычный redirect — это 302, а браузеры и XHR при 302 исторически могут повторить исходный метод на новом адресе: получился бы PUT вместо GET. Middleware Inertia превращает такие редиректы в 303 See Other — однозначно «теперь сделай GET».

  • Ошибка валидации — это тоже редирект: 302 back + errors в сессии
  • errors приходит как shared prop, а не 422 JSON
  • Состояние формы (useForm) переживает редирект с ошибками

optional и defer — не вычислять лишнее

Prop значением вычисляется на каждом запросе, даже если partial reload попросил другое поле. Inertia::optional откладывает и вычисление, и отправку до явного запроса через only; Inertia::defer не отправляет в первом ответе, а клиент сам дозапрашивает его сразу после рендера.

  • Комментарии — optional: не нужны, пока не долистали
  • Тяжёлая статистика дашборда — defer: страница видна сразу
  • Inertia::merge добавляет новые данные к старым — «показать ещё»

Pinia на уровне модуля — общий стор на сервер

SSR-сервер — долгоживущий процесс Node, рендерящий страницы для всех посетителей подряд. const pinia = createPinia() на верхнем уровне модуля создаёт один store на весь сервер: посетитель A записал имя — посетитель B получил его в разметке. Inertia 3 вызывает withApp(app) на каждый рендер — именно там нужно создавать Pinia.

  • withApp — единственное место для Vue-плагинов
  • window, localStorage на верхнем уровне компонента роняют SSR
  • /studio/* исключены через withoutSsr — индексация там не нужна

usePoll и useHttp

Не каждое обновление данных — это визит Inertia. usePoll делает периодический partial reload с автостопом при размонтировании и замедлением в фоновой вкладке; useHttp обращается к обычному JSON-эндпоинту (например, проверка уникальности слага) без смены страницы и истории.

  • usePoll(15_000, { only: ['counts'] }) — обновляет только счётчик
  • Замедление в фоновой вкладке — не греет сервер зря
  • useHttp не трогает history и объект страницы
