Redis Lab

Кэш, локи, rate limit, Streams

Redis как кэш, хранилище сессий, примитив синхронизации и брокер событий: cache-aside, distributed lock, rate limiter, Streams, XAUTOCLAIM, Pub/Sub-дашборд.

Стек: Laravel 13, PostgreSQL 18, Redis 8. Уровень: Средняя.

Кэш карточки и cache stampede

Читаем из Redis, при промахе идём в PostgreSQL и кладём результат с TTL; при записи ключ инвалидируется. Ловушка: истёкший ключ популярного товара обрушивает сотни запросов на базу, поэтому перестройку кэша защищает короткий лок.

  • Промах, TTL и инвалидация DEL
  • volatile-lru вытесняет только ключи с TTL
  • Лок на перестройку против stampede

Лок с токеном и TTL

SET NX PX создаёт ключ только если его нет и снимает лок по таймауту даже при падении процесса. Освобождать нужно Lua-скриптом с проверкой токена, иначе можно удалить чужой лок.

  • NX — только если ключа нет, PX — TTL
  • Уникальный токен владельца
  • Проверка и DEL атомарны в Lua

Скользящее окно на ZSet

Лимит «не больше 5 заказов в минуту» держится в отсортированном множестве, где score — время запроса. Все три шага собраны в один Lua-скрипт, иначе между ZCARD и ZADD проскочит гонка.

  • ZREMRANGEBYSCORE чистит старые записи
  • ZCARD считает остаток окна
  • PEXPIRE удаляет ключ неактивных пользователей

Одна команда и целая операция

Каждая команда Redis атомарна, но цепочка «прочитать, проверить, списать» — нет. Lua-скрипт выполняется как одна неделимая операция, поэтому резервирование стока не уходит в минус.

  • Redis однопоточен: скрипт не прерывается
  • EVAL с KEYS и ARGV
  • Альтернативы: MULTI/EXEC и SET NX

Consumer group и PEL

Stream — журнал, из которого запись не пропадает при чтении. Группа делит записи между воркерами, а выданное, но не подтверждённое лежит в PEL до XACK; повторную обработку гасит идемпотентность.

  • XADD, XREADGROUP, XACK
  • PEL — аналог unacked в RabbitMQ
  • Запись висит в PEL, пока её не заберут явно

XAUTOCLAIM вместо DLX

У Streams нет автоматической повторной доставки и dead-letter: зависшие записи забирает воркер-«надзиратель». Счётчик попыток хранится в Hash, потому что сама запись неизменяема.

  • XAUTOCLAIM по min-idle-time
  • Счётчик попыток отдельным ключом
  • После лимита запись уходит в orders:dlq:stream
