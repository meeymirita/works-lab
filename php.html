Чистый PHP Lab

Фундамент без фреймворка

Чистый PHP 8.4 без фреймворка: strict_types и copy-on-write массивы, суперглобалы, замыкания и генераторы, магические методы — и своими руками роутер, DI-контейнер, PDO-слой, сессии и CSRF.

Стек: PHP 8.4, PDO, PostgreSQL, Composer (PSR-4), PHPUnit. Уровень: Базовая.

strict_types и сравнения PHP 8

Один declare меняет поведение вызовов функций в файле, а нестрогое сравнение в PHP 8 изменилось. Ловушка: null == 0 в PHP истинно, в JavaScript нет.

  • declare(strict_types=1) действует на весь файл
  • таблица == до и после PHP 8
  • union и nullable типы

Значения с copy-on-write

Массив в PHP передаётся по значению, а физическое копирование откладывается до первой записи. Вывод: функция не изменит исходный массив, пока вы не попросите ссылку явно.

  • присваивание копирует логически, а не сразу
  • by-value против by-reference
  • array_filter сохраняет ключи, usort их сбрасывает

use, callable и yield

Замыкание захватывает переменные только явно и по значению на момент создания. Генератор читает данные порциями, поэтому файл в десять гигабайт не занимает память.

  • use по значению и по ссылке
  • fn как автозахват
  • yield, yield from, свой Iterator

На чём стоят фасады и Eloquent

__get и __set прячут атрибуты модели в массив, а __callStatic перенаправляет статический вызов на объект из контейнера. Фасад — не синтаксис, а несколько строк кода.

  • __get, __set, __isset
  • __call для динамических where*
  • __callStatic как механизм фасадов

Autowiring через Reflection

Контейнер сам читает конструктор класса, разрешает зависимости по типам и рекурсивно строит граф. Единственное, что нужно указать явно, — реализацию интерфейса.

  • bind и singleton
  • ReflectionClass и getParameters()
  • интерфейс без биндинга: понятная ошибка

SQL-инъекции и цепочка обработчиков

Конкатенация ввода в SQL открывает инъекцию, prepared statement передаёт значение отдельно от кода. Middleware собираются в «матрёшку» вложенных замыканий через array_reduce.

  • prepare и именованные плейсхолдеры
  • транзакция, CSRF-токен и hash_equals
  • порядок «до» и «после» у middleware
