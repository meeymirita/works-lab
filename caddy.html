Caddy Lab

Edge — веб-сервер и reverse proxy с автоматическим HTTPS

Один Caddy перед сайтом, API, WebSocket и PHP: Caddyfile вместо nginx + certbot, HTTPS из коробки, балансировка, безопасность, своя сборка через xcaddy.

Стек: Caddy 2.11.7, Docker Compose, Node.js 24, PHP 8.4-FPM, xcaddy / Go. Уровень: Средняя.

Один файл вместо nginx + certbot

Caddyfile без расширения в текущей папке caddy run подхватывает сам. admin off отключает Admin API, если он не нужен прямо сейчас — иначе через него же идут start/stop.

  • caddy run — без аргументов, Caddyfile из текущей папки
  • admin off, если Admin API не нужен
  • caddy start/stop — фон, управление через Admin API

handle: часть путей на бэкенд, остальное — статика

handle /api/* перехватывает только свой префикс, второй handle без пути — всё остальное отдаёт file_server. Порядок блоков handle друг друга не перекрывает, в отличие от route.

  • handle /api/* { reverse_proxy ... }
  • handle { file_server } — всё остальное
  • root * задаёт корень для статики

Проксируется без единой спецнастройки

reverse_proxy сам распознаёт заголовки Upgrade/Connection и держит двусторонний поток — отдельной директивы под WebSocket в Caddy нет.

  • Тот же reverse_proxy, что и для HTTP
  • Upgrade/Connection подхватываются автоматически
  • Проверяется обычным WebSocket-клиентом

Домены .localhost без единой настройки TLS

Без единой строчки про сертификаты app.localhost и api.localhost уже на HTTPS — Caddy сам решает, локальный CA это или настоящий ACME, по имени домена.

  • auto_https включён по умолчанию
  • 80/443 требуют прав — sudo или setcap
  • .localhost резолвится в локальный CA

round_robin между несколькими адресами

reverse_proxy принимает несколько адресов сразу — lb_policy задаёт стратегию. Без неё уже работает round robin по умолчанию.

  • Несколько адресов в одном reverse_proxy
  • lb_policy: round_robin, weighted, ip_hash, cookie
  • X-Backend в ответе показывает, кто ответил

Применить конфиг, не перезапуская процесс

localhost:2019 по умолчанию — HTTP-интерфейс самого Caddy: читает текущий конфиг, переводит Caddyfile в JSON не применяя и накатывает новый конфиг без простоя.

  • GET /config/... — чтение текущей конфигурации
  • POST /adapt — Caddyfile → JSON, без применения
  • caddy reload — тот же API под капотом
