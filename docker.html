Docker с нуля до релиза: контейнеры и их жизненный цикл, образы и слои, Dockerfile, multi-stage и безопасность, сети, тома, Compose, registry, GitHub Actions, итоговый стек CoffeeShop.

Порядок инструкций решает скорость сборки

Каждая инструкция Dockerfile — слой, а изменённый слой сбрасывает кэш всех слоёв ниже. Поэтому сначала копируют только файлы зависимостей и ставят пакеты, а код — после.

  • Образ — стопка слоёв только для чтения
  • COPY . . до npm ci заново ставит пакеты при каждой правке
  • Удаление файла в следующем слое образ не уменьшает

Одно слово между быстрой остановкой и десятью секундами

docker stop шлёт SIGTERM процессу с PID 1. Если entrypoint-скрипт запускает приложение без exec, PID 1 остаётся у sh, сигнал не доходит до Node, и через 10 секунд приходит SIGKILL (код 137).

  • ENTRYPOINT + CMD — всегда в exec-форме
  • exec заменяет скрипт приложением
  • Проверка: время docker stop и код выхода

Сборка отдельно, запуск отдельно

В итоговый образ попадает только последний этап. Инструменты сборки остаются на «стройке»; distroless-образ без оболочки и npm не содержит и уязвимостей этих пакетов.

  • COPY --from=этап переносит результат
  • Итоговый образ работает от nonroot
  • Trivy: у старого образа 8 HIGH, у distroless — 0

Данные переживают контейнер

Файловая система контейнера исчезает вместе с ним. У PostgreSQL 18 том монтируется в /var/lib/postgresql: старый путь /var/lib/postgresql/data образ отвергает.

  • Именованный том для базы, bind mount для файлов хоста
  • Анонимные тома «осиротевают» после docker rm
  • pg_dump — бэкап, том бэкапом не является

Имена вместо IP, изоляция вместо открытых портов

В пользовательской сети работает встроенный DNS: api находит db по имени. Две сети (front и back) не дают сайту видеть базу, а у базы нет опубликованных портов.

  • В сети bridge по умолчанию DNS по именам нет
  • -p публикует порт, EXPOSE — только подсказка
  • Диагностика: ps -a → logs → network inspect → nslookup

«Запущен» не значит «готов»

Обычный depends_on ждёт только старта контейнера, а база ещё инициализируется — отсюда ECONNREFUSED. healthcheck и condition: service_healthy ждут настоящей готовности.

  • Знак $$ в healthcheck.test: подстановку делает оболочка в контейнере
  • Профили, override и prod-накладка: один набор файлов на все режимы
  • restart, лимиты памяти, ограничение логов — в compose.prod.yaml
