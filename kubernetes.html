Kubernetes Lab

Kubernetes и Helm с нуля

Kubernetes и Helm с нуля, стек CoffeeShop из Traefik-лабы переезжает из Compose в кластер kind: архитектура и kubectl, Pod и Service, Deployment и обновления, Ingress (Traefik), хранение данных и StatefulSet, ConfigMap и Secret, пробы и ресурсы, RBAC и NetworkPolicy, автомасштабирование, Prometheus и Grafana, Helm (chart, шаблоны, репозитории, релизы), umbrella chart и Kustomize.

Стек: Kubernetes v1.37.0, kind v0.33, kubectl, Helm 4, Traefik v3.7 (Ingress), Prometheus / Grafana. Уровень: Средняя–высокая.

Желаемое состояние вместо команд

Deployment создаёт ReplicaSet, а тот следит, чтобы Pod'ов с нужными метками было ровно replicas. Смена образа запускает rolling update: старые Pod уходят по одному, новые приходят, сервис не останавливается; плохую версию откатывает rollout undo.

  • replicas: 3 — утверждение, а не разовая команда
  • selector.matchLabels обязан совпадать с метками шаблона
  • maxSurge и maxUnavailable задают скорость волны

Стабильный адрес и один вход

У Pod'ов адреса меняются, поэтому перед ними стоит Service: находит Pod по меткам, берёт только готовых и имеет DNS-имя. Снаружи на несколько Service смотрит один Ingress, который выполняет контроллер (у нас Traefik).

  • selector Service = метки Pod
  • db.default.svc.cluster.local внутри кластера
  • Ingress — только правила; без контроллера они мёртвый текст

Том переживает Pod, пароль живёт отдельно

База хранит данные на PersistentVolumeClaim: Pod можно удалить, том и данные остаются. Для БД используют StatefulSet. Конфиг и пароль выносят из образа в ConfigMap и Secret; base64 в Secret — кодирование, а не шифрование.

  • PVC → PV → диск; StorageClass создаёт тома сам
  • StatefulSet: стабильные имена и volumeClaimTemplates
  • secretKeyRef берёт одну переменную под своим именем

Готов и жив — разные вопросы

readinessProbe убирает Pod из Service, livenessProbe перезапускает контейнер. requests бронируют ресурсы и служат базой для HPA, limits по памяти — потолок, за которым OOMKilled. Диагностика идёт по таблице «статус → причина».

  • Running 0/1 — не проходит readiness
  • OOMKilled — превышен limits.memory
  • describe pod и Events — первая команда любого разбора

Права, запреты и автоскейлинг

RBAC выдаёт права через Role и RoleBinding, securityContext отнимает лишнее у контейнера, NetworkPolicy запирает базу от всех, кроме API. HPA сам считает число реплик по CPU, но без requests и metrics-server показывает <unknown>.

  • kubectl auth can-i --as проверяет права
  • политика сети работает только если CNI её применяет
  • HPA растёт быстро, падает через окно стабилизации

Один chart, любое окружение

Chart — шаблоны манифестов плюс значения по умолчанию, release — установка с журналом ревизий. Отличия dev и prod лежат в файлах values; upgrade с --atomic откатывается сам, а rollback возвращает прежнюю ревизию.

  • helm template — репетиция: читай готовый YAML
  • toYaml | nindent N — главный приём и главная ловушка
  • umbrella chart собирает db, api и web одной командой
